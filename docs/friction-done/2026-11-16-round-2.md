## Common causes

1. **Parallel branches collide in a few large files**: the CLI's one file of commands and options, design.md, the
   engine's one index. The fix is boundaries: one module per command, docs per subsystem, a core entry.
2. **Feedback that hides its cause**: a cache rebuild that looks like a slow test, a background run that looks
   stalled, a lint error found 15 minutes into premerge. The fix is tools that say what they do: the rebuild's reason,
   a line per finished test file, lint of the changed files, premerge stopping at the gates.
3. **Before/after work done by hand**: another commit's code, snapshot keys, frame rates. The fix is one command each.

## What changed, by item (commits on the round's branch)

**1. Quick wins** (742ef44, 9a1f8a5)
- `npm run lint:changed [-- <ref>]` (scripts/lint-changed.ts). Premerge skips the test suites when typecheck or lint
  fails (`--keep-going` runs them), and warns about default-suite files over 40 s and tests over 30 s.
- The game-data cache hashes only the data sources the build runs (`dataSources`, traced from gameData.ts) and the
  engine modules they use; a rebuild prints which inputs changed since the last entry written (`last-inputs.json`).
- `framesOf` / `secondsOf` (units.ts) and `withSeconds(scenario, s)`; CLAUDE.md: never a literal frame rate.
- `node scripts/with-lock.ts <cmd>`: premerge's lock (scripts/testlock.ts) for long CPU jobs.
- `node scripts/at-commit.ts <ref> [--patch f]`: another commit's code under scratch/at/<hash>, its own packages linked.
- scripts/vitest-progress.ts: a line per finished test file; premerge and snapshots.sh add it off a terminal.
- tests/snapshot.ts exports the one writer; `node scripts/snapshot-keys.ts <file> --rename <re> <to>` (counts only).
- Status tests match behaviour with `toMatchObject`; one test pins the record-only fields.
- `PolicyObserver.check` / `.press`: every start check with its answer, every press.
- Pending shards balanced by measured time (tests/slow/pending-costs.json, written by snapshots.sh): the four shards
  carry 54 / 54 / 54 / 54 s of check time instead of 79 / 62 / 46 / 30 s by hit count.

**2. CLI: one module per command** (951b373). `packages/cli/src/commands/<name>.ts` (17 modules: usage lines, options,
run, typed from the module's own options) registered in commands/index.ts; cli.ts (817 → 56 lines) parses once and
dispatches; `mergedOptions` refuses an option two commands declare differently. `efsim --help` is byte for byte the
old text.

**3. Engine core vs planning** (440e660). `packages/engine/src/core.ts` (`@efsim/engine/core`) is the core; the
planning code (12 modules, 6.0k lines) moved to `packages/engine/src/planning/` and imports the core only through
`../core.ts`; the façade gained the seven internals planning read; `nextBasics` / `diveOf` moved to
timeline/buttons.ts (the rule driver no longer imports the search). Lint enforces: the core never imports planning,
planning never imports a core module directly, the data package imports only `@efsim/engine/core`. The cache's
engine trace goes through core.ts (the same 11 files). `@efsim/engine` re-exports both.

**4. Log tooling as a package** (a60e46f). `packages/logs` (`@efsim/logs`, 17 modules, 6.6k lines): the importer
(zmdlogs.ts from @efsim/data; logs.ts, zmdraw.ts) and the log check with its tools. The logcheck ⇄ enginecheck cycle is
broken (assumptions.ts); reports.ts holds what `efsim zmdlogs` computes, so the command only checks arguments.
`@efsim/cli` re-exports `@efsim/logs`. setup-worktree links every workspace package, and in the main checkout adds
the missing link npm would make (so main runs after the merge without `npm install`).

**5. design.md split** (4b2dc1a). design.md (2,696 → 121 lines) keeps the goals, principles, layers and a map;
the sections are in docs/design/{data,timeline,search,gear,rules,damage,tests,notes}.md. 128 citations in code,
schemas and docs and every Markdown link were rewritten (the journal and reports keep their wording; their links
resolve). `npm run links` (scripts/check-links.ts) and tests/doc-links.test.ts check relative links and anchors.
