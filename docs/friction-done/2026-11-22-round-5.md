## Common causes, ranked by what they cost

1. **The shared test lock dominated wall time** (six of the eight accuracy reports: Arcane 4, Liino 1, Perlica 5,
   Rossi 5, rule-objective 3, Yinglung 3). Eight agents at once: every measure, smoke, snapshots, team-ab and premerge
   waited 10–60 min; runs were killed by the Bash tool's background limit while still queued; and because measure
   read the working tree when its turn came, agents idled through the wait rather than edit. Two separate causes: one
   agent's batch of rule searches held everyone (arrival order only), and nothing tied a queued run to the code of
   the moment it was queued.
2. **A done line that lied** (Perlica 4): premerge printed `EFSIM-DONE premerge pass` after a failed test step when
   its limit killed it, because its EXIT trap read `$?`, 0 in a shell killed by a signal. The one line every agent
   waits on.
3. **The views stop where diagnosis starts** (all eight accuracy reports, about 20 scratch scripts): world time
   between two moments, a lane's world-time length, which hits a change moved, which casts a placement change moved,
   what the replay made of a logged cast event, fallback matches hiding a missing modifier, ticks against the
   replay's, buff windows joined with the log's, statuses, consumed layers.
4. **Silent behaviour and misleading names** (Arcane 1 and 3, Liino 3 and 4, Rossi 1, Twilight 2): batched log
   timestamps, `withLoggedCasts` absorbing an entity's events, a `launch` frame delaying later casts, `hits --json`'s
   `predicted` not being the verdict's number, a raw lane's end read as an expiry, how the placement picks among
   groups sharing a key.
5. **Merging branches** (the lead): branches that each passed premerge broke each other once merged; adding a branch
   meant stopping a running snapshots job.
6. **Repo hygiene** (rule-objective 2, round-4 friction 3 and 4, Twilight 4): prettier with no config rewrote a whole
   file; heredocs and the guard; `grep -r` naming the hold-out snapshot file.

## What changed, by cause (commits on the round's branch)

- **Lock and queue** (d98b497, 6032c21): fair shares in scripts/testlock.ts (a worktree's n-th waiting job or short
  job counts as arriving n × 20 min later); the first waiting line gives the estimated wait plus run against the
  2 h background limit (a warning past it); a kill in the queue says so on the DONE line; measure and team-ab fix
  their code at queue time (scripts/at-commit.ts `snapshotCommit`: a commit of the working tree from a temporary
  index, run in its own worktree, removed after; measure `--live` for the old way); team-ab's identity check as a
  short job and the 32 seeds only for the moved teams; CLAUDE.md and docs/design/tests.md "Limits": every locked job
  in the background from the start with the 2 h limit. Not done, judged: a hard one-job-per-agent cap (fair shares
  do it without idling the machine), more jobs sharing the side lane (two measures, or a measure beside a test suite,
  would slow both past the tests' timeouts and make measurements incomparable: the snapshot makes the wait free
  instead), a limit that starts at the lock (the limit is the Bash tool's, not ours).
- **premerge's done line** (1f117a9): scripts/done-line.sh, "pass" only from the script's own end, "killed" from a
  signal trap (long steps run in the background and are waited for, so the trap runs at once and stops them);
  tests/done-line.test.ts kills a stub mid-step.
- **Views** (d98b497, cec2dd6, c9247da): `zmdlogs worldtime`, `lanes --world`, `measure --hits` (hits.txt),
  `measure --changed placement` naming moved casts, `zmdlogs replay` EVENT lines (`loggedCastFates`, sharing
  withLoggedCasts' matcher), `groups` fallback matches by event with their median ratio, `hits --json`
  `verdictReading` / `verdictError`, `efsim assumptions`, `efsim kit` skill groups and hit applications.
- **Silent behaviour, in the docs** (c9247da): data.md "Timestamps are batched", "One key, several groups", and
  misreadings (a raw lane's end, fallback matches, `predicted`, the replay's EVENT lines); KitHit.launch's and
  earliestStart's doc comments; question-table rows (gamedata find / who, assumptions, worldtime, measure --hits, the
  census window in ms).
- **Merging** (6032c21): `npm run merge -- <branch>…` runs `npx vitest related --run` on the code both sides changed
  and merges a batch with one snapshots run at the end.
- **Hygiene** (c9247da): `.prettierignore` (`*`) and "no code formatter" in CLAUDE.md; the commit-message recipe
  first among the worktree rules; `grep -r --exclude-dir=holdout --exclude='*holdout*'`.
