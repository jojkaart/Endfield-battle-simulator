## For the lead: the hook (raise with the owner)

scripts/bash-guard.ts refuses, with the safe form in its message: a heredoc; an inline interpreter script (`python3
-c`, `node -e`, `perl -e`, `bash -c`) over several lines or with a backtick; a multi-line `git commit -m`; a backtick
the shell would run (outside single quotes, not escaped). It does nothing until wired; agents don't edit
.claude/settings files, so the owner would add to .claude/settings.json:

```json
{ "hooks": { "PreToolUse": [ { "matcher": "Bash", "hooks": [ { "type": "command", "command": "node scripts/bash-guard.ts" } ] } ] } }
```

In a worktree the command runs from the worktree (its own copy of the script). Exit 2 refuses the call and shows the
reason to the agent; a malformed input never blocks. `node scripts/bash-guard.ts --check '<cmd>'` tries one by hand.
Without the hook the doc damage check still catches the worst case (a doc written with substitutions) at `npm test`.

Also a decision for the lead: measure's and snapshots:update's hold-out lines now print how many moved hold-outs
have each operator (never a log id), as the fight totals report asked. If the owner wants hold-outs blinder than
that, `directionSummary`'s byOperator block in scripts/accuracy.ts is the one place to drop. **The lead dropped it
(2026-11-23):** which operators the moved hold-outs have tells what the hold-outs contain; the field kinds stay.
