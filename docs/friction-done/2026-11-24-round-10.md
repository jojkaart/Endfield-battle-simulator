## Common causes, ranked by what they cost

1. **Every new question re-runs every replay** (one-sided point 1, misprediction point 1, round 9 point 4): the views
   cache aggregates, not the rows a new question needs, and a fresh worktree recomputes even the aggregates. Three
   scratch scripts of about 2 minutes each, a Python pass, an hour's rebuild of the check's internals, 171 s per new
   worktree.
2. **The printers leave out what they don't show, without a word** (one-sided point 4, physical-statuses points 2, 3
   and 5): `efsim kit` printed a trigger's event but not its actions, a skill's duration but not its ends or the jumps
   onto it; `gamedata tree` dropped a branch of only presentation as if it weren't there; `zmdlogs hits --from` was
   accepted and ignored, because the CLI's one shared parse accepts any command's option. Each cost a hunt in the kit
   JSON or a scratch script, and one question (Empyrean's branches) was left open for it.
3. **Knock-ons found in a later step than the one meant to show them** (misprediction point 6, physical-statuses
   point 1): a feature test pinning d774's total failed only at premerge (a second 8-minute run); a `--patch` the tree
   already had failed only after the measure queue.
4. **Shell programming and the habits it feeds** (the lead's item; one-sided point 2, physical-statuses point 4, round
   9 point 1): premerge.sh, snapshots.sh, done-line.sh and fetch-data.sh held traps, loops and pipelines that no test
   but done-line's covered; the bash guard is now wired by the owner, and no script is left to imitate.
5. **Two places for one answer** (round 9 point 2, misprediction point 2): two offset detectors with one explanation
   in one of them; several "error" fields on HitRecord with no word on which one the check judges.
6. **One commit's tools against another's code** (misprediction point 3): a probe being edited couldn't run on an
   at-commit tree without copying it in by hand.
