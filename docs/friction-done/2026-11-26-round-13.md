## Common causes, ranked by what they cost

1. **A question asked across logs has no view, so each agent builds the plumbing again** (enemy-clock points 1 and 3,
   holds-and-placement point 3): five scratch probes for "how late does each clock run across a combo", each
   rebuilding the logs, the stops, worldMs by stop kind and the log's Stagger spans (tickstag.ts's code copied a third
   time; a per-pair cut misled for a while); the hold placement's dropped bounds counted per log only, so a
   systematic conflict (combos in a Stagger) was never seen; a variant's moved hits found by diffing two `zmdlogs
   hits` runs three times. The costliest by far: the enemy-clock round's main finding took most of its session.
2. **Options thread by hand, so a new view or script misses one** (holds-and-placement point 2, damage-factors point
   2): `--assume` reached replay, hits, totals, clock and check, not holds, ramp, bursts, stops or differences, each a
   code edit at the moment after a measure; measure parsed its options only inside the lock, so `--help` cost a 5-minute
   queue.
3. **A decision isn't recorded where it is made** (holds-and-placement point 1, backlog points 1–2): the in-turn rule's
   refusals needed a temporary print (half an hour, and a mixed run from settleCheck's third pass); a burst's cause is
   still a search. Both live in files the accuracy agent held: carried.
4. **The work's file split doesn't follow where the causes live** (damage-factors point 1): of five damage factors,
   four causes sat in files another agent held, so three fixes went back as held-back diffs. The lead's call; a tool
   and a convention for it below.
5. **A guess compiled as data can't be a reading** (enemy-clock point 2): the ComboSkill curve needed patches in the
   data compiler, another agent's directory, and two queued measures. Carried (compiler and engine).
6. **Smaller**: two pairings of casts (settleCheck's and measure's text diff), the hold-outs' output rule only in a round
   write-up, a layered buff listed once with nothing saying so, an edits-file separator that an append block doesn't
   need, a patch failure that didn't say which hunk.

## For the lead

- **The brief's file split** (damage-factors point 1). What would make it cheaper to get right:
  - *See where a lead's causes tend to live before splitting*: `node scripts/lead-files.ts <ids, operators, words>`
    (seconds) lists the code files earlier commits naming them changed, with the files another worktree's branch has
    changed since main marked. A lead whose history points into the replay (buffreplay.ts, logcasts.ts) belongs with
    the agent holding the replay, whatever the lead's name suggests ("damage factors" sounded like kit code).
  - *Split by question where the cause is unknown*, and give file ownership only where it is known; or say up front
    that a fix in another's file goes back as a measured diff.
  - *A convention for handing a measured diff on* (the damage-factors round made it up): the diff in docs/tried/ under
    "held back", its header naming the file's holder, the measure it was sized with (`measure --at HEAD --patch` and
    `--hits`) and what a general rule would need; the lead applies it after the holder's merge, or hands it to the
    holder's next brief, and deletes it once adopted (as 2026-11-26's loggedEntries fix was). `measure --patch
    docs/tried/<file>` re-measures it on the merged code.
- **The 6 live backlog points all need the replay, placement, compiler or engine**: points 1 (the placement's `--why`
  record, with settleCheck on `pairCasts`), 4 (the curves as a reading) and 6 (the buffreplay.ts split) suit the next
  agent that holds those files, between accuracy tasks; a split by move only wants the file to itself.
- `zmdlogs holds --dropped --all` and `zmdlogs clocks --all --by operator` are the first evidence for the accuracy
  list's "holds per stretch" and "combos hold every clock" (counts in the backlog).
- tests/zmdlogs-cli.test.ts fails when a new subcommand is in neither REPLAYING nor NOT_REPLAYING: put it in one.
