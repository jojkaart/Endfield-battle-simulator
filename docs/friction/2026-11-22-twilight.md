# Twilight's excess over its model (2026-11-22)

Task: find why Laevatain's Twilight lasts 0.1–4.6 s longer than modelled in the closed
windows, and fix it or register the best reading (branch of the Twilight diagnosis, base
1ab4647). The answer was a probe the tools don't offer: a second buff of hers (Forgeborn's
20 s) runs as long past the replay, so the excess is her buffs' clock, not Twilight's.

## 1. A buff's holds past its modelled end can't be read without editing the kit

- **What happened:** `zmdlogs replay --trace-buff` stops tracing a buff when the replay's
  instance ends, so the holds the game's longer window collects later (a combo, another's
  stop) are missing. To count them I set Twilight's kit duration to 45 s; the kit check
  refused it ("buff durations differ from the compiled SkillData"), then refused a short
  `dataOverride.duration` reason ("must NOT have fewer than 10 characters"): three edits of
  a tracked kit file, restored by hand after each run, and a measure that had to wait in the
  queue with the patched kit on disk (no other edit of it possible meanwhile).
- **Cause:** the trace reports expiry changes of the live instance only; there is no "holds
  up to time t, whatever the expiry" query, and no per-run duration override.
- **Fix:** `zmdlogs replay --trace-buff owner:id --long` (or `--buff-duration owner:id=s`,
  replay-only, not a kit edit) that keeps the instance alive and prints the cumulative held
  frames at each step; `measure --kit-duration owner:id=s` for the same in measurements.
- **Why it helps:** every "runs longer than its model" question (Twilight, Rossi's crit DMG,
  Scorching Heart, Liino's volleys) starts with this count.

## 2. No view compares a listed buff's end with the replay's own expiry

- **What happened:** the decisive probe (Forgeborn Scathe's `buff_wpn_sword_0006_valid`,
  a plain 20 s buff from the same ultimate) took a raw dump per log, `zmdlogs lanes`
  per log for the last listed / next unlisted hit, the replay's trace for the expiry, and a
  script to join them (scratch/twl/fg.ts, both.ts). I also first read the raw lane's end as
  the expiry; it is a hit's time near the last listed hit (c83c 73.585 = her attack1 hit),
  which `zmdlogs raw`'s help doesn't say.
- **Cause:** `differences` and `timing` work per hit; nothing works per lane end. The raw
  view's `start–end` reads like a buff's life.
- **Fix:** `efsim zmdlogs ends [fixture…] --buff <re>`: per lane with a natural end (not
  refreshed, not the fight's end), the bracket [last listed hit, next unlisted hit of its
  hitters], the replay's expiry with holds past it counted (item 1), and the excess; a
  summary over logs. Say in `zmdlogs raw`'s help that a lane's end is a logged event's time.
- **Why it helps:** it is the general clock probe; it would have shown in minutes that every
  buff of hers in these windows runs ~1–3 s over, and it is what the buff-clock question in
  open-problems now needs over every log.

## 3. "The log's bracket of a state" is hand-written every time

- **What happened:** the Twilight brackets (last enhanced cast, first plain cast) were a
  scratch script again (the 2026-11-18 agent wrote twilight2.ts / dneed.ts / holds.ts in its
  own worktree's scratch/, gone for me), plus a parser for `zmdlogs instances` text.
- **Cause:** no command takes "a kit buff and the casts that show it on / off".
- **Fix:** `efsim zmdlogs windows <fixture…> --kit-buff owner:id --on <cast regex> --off
  <cast regex>`: per replay instance, the log's bracket and the residual against the
  replay's end (with item 1's holds); `--json` for fits.
- **Why it helps:** Twilight, Arcane's modes, Liino's stance, Typhoeus's window are all
  "a state the casts show".

## 4. The worktree guard refuses a heredoc into a scratch file

- **What happened:** `cat > scratch/twl/restarts.ts <<'EOF' … EOF` was refused as "too
  complex to verify", after an earlier heredoc in the same session had run. Rewritten with
  the Write tool.
- **Cause:** as CLAUDE.md says, the guard judges the whole text; the rule is easy to forget
  once a heredoc has passed.
- **Fix:** none needed beyond CLAUDE.md; a lint-like hint in the refusal ("use the Write
  tool for files") would save the retry.
