  more, so states with different futures can be merged and pruned.

## 3. Simplifications (each checked against 1's snapshots)

1. **Kit values from the data.** The loader only checks that named keys
   exist; hit frames, events, factors, poise, SP and energy are compared
   with the compiled data only in packages/data/test/skillCompile.test.ts,
   with one shared list of 156 known differences. → the loader fills them
   from the compiler and refuses a differing hand-written value unless the
   kit says why (`dataOverride`). About 2,000 hand-written values (≈20% of
   the kits' structure) go; a patch that changes a number fails loudly. Also:
   a test that every action type in the fetched data is handled or on an
   ignore list; buff durations from the data's CreateBuff assignments; one
   SkillData walker instead of three.
2. **The checker reads facts from the replay** instead of trying
   alternatives: Link stacks, cast-bound buffs, combo event counts, layers,
   Corrosion level. End point: simulate the logged casts and compare hit by
   hit. Blockers: per-hit crit from the log; casts without logged damage
   (inferred from buff lanes or skill events); time stops (the ±0.5 s /
   ±10% slack); one enemy-state replay instead of two. (2026-10-25: done
   but for the enemy's side of a landing, crits and casts without damage
   included; the end point is `zmdlogs check --simulate`, a diagnostic;
   time stops and the second enemy replay remain: journal.)
3. **Engine structure.** Pending hits, actions, energy and jumps as one
   scheduled list with the clock each runs on (both bugs in 2 come from a
   list missing in a shift function); one documented order within a frame
   (today ties depend on operator ID order); `timeline.ts` (2,750 lines)
   split along its existing seams. (2026-10-25: done; ties between hits
   still go by operator ID, now one documented rule; design.md "Engine

## 5. Likely bugs

- *Confirmed:* Stagger counts twice in the timeline: `damageOptions`
  passes `staggered: true` (the ×1.3 Stagger zone in damage.ts) and adds a
  `multiplicative` 0.3 as well, so a Staggered enemy takes ×1.69. The log
  check passes `staggered: false` and takes the ×1.3 from the log, so it
  didn't catch it; it also never applies "DMG vs Staggered" modifiers
  (attribute 61, 8 gear lines). Lead: 458b's six Laevatain
  `normal_skill_during_ult` mismatches are exactly ×1.3000.
- *Confirmed:* in a team the search only offers what can start now: a
  swap can nearly always start at the state's frame, which makes "now"
  true and drops every skill that could start a few frames later (12 of 14
  decision states of si-laevatain's rotation had one). Skills then start
  only on frames where a basic attack or swap starts.
- A combo waiting for its window looks only at hits and delayed actions,
  not enemy actions, bursts or ticks (catcher-counter: the charge at 210);
  after such a wait, availability, cooldown and input mapping aren't
  re-checked.
- Smaller: `enemyFrozenUntil` isn't moved by a time stop; ending a buff
  for one member skips the cooldown rebase; a cast inside an advance
  records stale SP; the perfect dodge adds SP outside `gainSp`; the
  search's expansion cap cuts silently; Solidification durations 5.75–8.75
  s (Talos) vs 6–9 s (End-DPScope's reading of the config; test 71).

## 6. Simplifications and reliability

- **Formulas:** the level coefficient is data (CharacterTable attributes 49
  and 25), not a formula in reactions.ts; resistance is stored three ways
  per enemy and disagrees for `eny_0125_fdcentur`; attribute caps
  (AttributeMetaTable) instead of literals; silent defaults (missing DEF =
  ×1, an undecidable buff `when` dropped, crit processors read without
  formulaItem, the ATK slot check skipped); a reaction / burst DMG zone
  missing (attributes 35–38 and 56–59, gear sets write them; dropped
  silently); `Modifier` without an attacker / defender side (Combustion's
  snapshot); stacking may mix two instances' modifiers; duplicate damage
  paths (landing's re-rounding, the checker's finisher, Arts Intensity
  summed twice).
- **Engine:** slow-downs don't extend what a cast creates (creation order
  answers in-game test 18, not a rule); buff ends and ticks as scheduled
  items (removes shiftBuff and two scans); per-stream RNG; SP with its own
  timestamp; `landHit`'s order as a table; duplicated end-of-action code.
- **Search:** results move ±4.5% with beam width (si-laevatain 2.05–2.15
  M, not monotone); pruning by macro state; dead deadlines in the state key
  (past `readyAt`, ended windows ...) keep equivalent states apart;
  `resourceWeight` hoards SP; report a beam spread.
- **Data / kits:** a Typhoeus `dataOverride` hides dbae's verified
  arrowrain hits; `skillGraph.ts` (a fourth SkillData walker) replaceable
  by the compiler's finalStrike / decorate mask, then `launch` filled (127
  values); ~110 of the 209 marks are a few compiler limits; buff durations
  filled; duplicated mask / FPS constants; catch-alls in kits.ts and
  buffreplay.ts.
- **Log check:** the enemy side and reactions from the replay (≈43 of the
  49 remaining fallbacks are one Arcane burst the replay doesn't predict);
  the negative control replays a different fight (scaled logs lose the
  enemy-HP track); a build fitter with structured `buildOverrides`
  instead of hand fits in notes; `--simulate` disagrees even on plain
  matches (b7b3 Tangtang 0 of 45): diff the modifiers by source.
